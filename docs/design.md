# Leslie UI 设计基线：Telegram Desktop 7.0.8 风格拆解

> 文档状态：后续 UI 开发基线，不代表当前原型已经全部实现
> 更新日期：2026-08-05
> 研究对象：Telegram Desktop Windows x64 7.0.8 及其同版本官方开源代码
> 适用范围：Electron 桌面外壳、聊天、设置、角色记忆、角色工坊及响应式表现层
> 不在范围内：消息生成、提示词顺序、角色卡、World Info、群聊、Swipe、模型适配、JSONL 和 Leslie 记忆数据格式

## 1. 一句话结论

Leslie 采用 Telegram Desktop 的核心设计方法，而不是复制 Telegram 的外观：

> 用稳定的会话列表组织入口，用低存在感的界面承载高密度内容，用一个强调色表达操作和状态；能用留白、底色和分隔线说明层级时，不再额外套卡片。

当前 Leslie 已经有正确的桌面双栏骨架，但视觉上比 Telegram 更“卡片化”：大圆角容器、重复描边、深阴影和嵌套卡片较多。后续优化的重点应是减法，而不是重写界面或增加装饰。

推荐方向：

- 保留“左侧会话、右侧聊天”的现有骨架；
- 宽窗口按需增加右侧详情栏，用于记忆、角色资料和 World Info；
- 减少设置页、记忆页和角色工坊中的独立卡片数量；
- 统一聊天、设置和工具页的颜色、尺寸、圆角、图标和状态表达；
- 保留 Leslie 自有名称、图标和品牌，不复制 Telegram 纸飞机、商标、插画或源代码资产。

## 3. Telegram 风格的本质

Telegram 风格不等于“蓝色、圆角、气泡”。真正构成辨识度的是以下组合。

### 3.1 内容先于容器

- 会话列表是连续平面，不把每个会话单独做成悬浮卡片；
- 聊天画布本身保持安静，主要由消息内容建立节奏；
- 工具栏、输入区和弹出菜单有明确边界，但不使用夸张阴影；
- 只有菜单、模态框、浮动提示等真正覆盖其他内容的元素才使用阴影。

### 3.2 高密度但不拥挤

Telegram 7.0.8 桌面会话行的普通高度为 `62px`，头像为 `46px`；名称、摘要、时间和未读状态在一行内完成信息分工。它紧凑，但不会把文字、图标和点击区域挤在一起。

Leslie 应采用 `64px` 普通会话行与 `48px` 头像，兼顾中文和现有角色头像。带第三行状态的特殊条目可增加到 `72px`，不能让所有会话都默认变高。

### 3.3 一个强调色，多种中性色

- 蓝色只负责选中、链接、主要按钮、在线或可操作状态；
- 大部分界面由白、灰、深蓝灰和轻微底色差组成；
- 成功、警告、错误色只在真实状态出现，不作为装饰；
- 同一页面不同时使用多种“品牌渐变”争夺注意力。

### 3.4 状态贴近对象

- 未读数贴近会话；
- 发送、生成和失败状态贴近对应消息；
- 模型状态贴近聊天头部或输入区；
- 记忆是否参与回复贴近“记忆”入口和记忆详情；
- 不用一个全局大横幅代替所有局部状态。

### 3.5 渐进展开

渐进展开是“先显示常用内容，需要时再展开高级内容”。Telegram 把搜索、会话、聊天保持在主路径，把资料、媒体、设置和低频动作放进详情栏、菜单或二级页面。

Leslie 对应做法：

- 日常聊天只显示角色、消息、输入和关键状态；
- 角色卡、记忆、World Info 和聊天管理从头部进入；
- Prompt Manager、供应商高级参数和兼容功能集中放入高级模式；
- 隐藏不等于删除，原 SillyTavern 能力必须始终可恢复访问。

## 4. 总体信息架构

### 4.1 桌面双栏

```text
┌──────────────────────────┬──────────────────────────────────────────────────┐
│ 会话栏                   │ 当前聊天                                         │
│                          │                                                  │
│ Leslie      新建  设置   │ 头像  角色名 / 模型状态       记忆  资料  更多   │
│ 搜索角色或会话           ├──────────────────────────────────────────────────┤
│ 全部  角色  群聊         │                                                  │
│                          │ 对方消息                                         │
│ 头像  名称        时间   │                                  用户消息        │
│       最近消息     状态   │                                                  │
│                          │ 系统状态 / 生成状态                              │
│                          ├──────────────────────────────────────────────────┤
│ 模型状态                 │ 附件  输入消息                          发送/停止 │
└──────────────────────────┴──────────────────────────────────────────────────┘
```

### 4.2 宽桌面三栏

当窗口足够宽且用户主动打开详情时，使用第三栏，不用覆盖聊天的大模态框：

```text
会话列表  →  当前聊天  →  当前角色详情
                           ├─ 角色资料
                           ├─ Leslie 记忆
                           ├─ World Info
                           └─ 会话设置
```

第三栏是“当前聊天的上下文”，不是新的全局导航。关闭后聊天宽度恢复，不能丢失输入草稿或滚动位置。

### 4.3 响应式规则

| 可用宽度 | Leslie 采用布局 |
| --- | --- |
| `>= 1180px` | 双栏；可按需打开 `300–360px` 第三栏 |
| `900–1179px` | 左栏 `300–340px`，右栏自适应；详情作为右栏内二级页 |
| `700–899px` | 左栏 `280–300px`，压缩次要文字；不同时显示第三栏 |
| `< 700px` | 单栏页面式导航；列表、聊天、设置详情互相切换 |

Telegram 7.0.8 源码的窗口最小宽度为 `380px`，左栏允许 `260–540px`，主栏最小 `380px`，第三栏为 `292–392px`。Leslie 不照搬其全部弹性范围，推荐：

```css
--leslie-sidebar-width: clamp(280px, 26vw, 380px);
--leslie-detail-width: clamp(300px, 24vw, 360px);
--leslie-chat-readable-width: 780px;
```

左栏以后可以允许拖动，但第一步不必为此修改数据；宽度偏好只存界面设置，不进入聊天或角色数据。

## 5. 核心页面规范

### 5.1 会话栏

顶部顺序固定为：

1. 产品标识、创建和设置；
2. 搜索；
3. 必要的筛选；
4. 会话列表；
5. 模型连接状态。

推荐尺寸：

| 元素 | Telegram 原值 | Leslie 采用值 |
| --- | ---: | ---: |
| 普通会话行 | `62px` | `64px` |
| 普通头像 | `46px` | `48px` |
| 搜索框高度 | `35px` | `36px` |
| 搜索框圆角 | `18px` | `18px` |
| 顶部图标按钮 | `40px` | `40px`，点击热区不小于 `44px` |
| 未读数字 | `12px bold` | `12px 600` |
| 未读徽标高度 | `19px` | `20px` |

条目结构：

- 第一行：名称、可选状态图标、时间；
- 第二行：最后消息或“继续最近会话”，右侧为未读/失败/处理中状态；
- 当前会话使用整行柔和底色，不再额外套大圆角卡片；
- 悬停与选中必须不同；键盘焦点再增加清晰焦点环；
- 普通行之间不强制画满宽分隔线，可使用缩进分隔线或只靠底色状态；
- 点击角色默认继续最近一次有实际消息的会话；只有明确的“新建会话”操作才创建空聊天。

筛选只保留真实可工作的类别。没有可靠未读数据时，不展示假的“未读”入口。

### 5.2 聊天头部

推荐高度 `56–60px`，固定在聊天上方。

左侧：

- `40px` 角色头像；
- 角色名，`15–16px / 600`；
- 第二行状态，`12px`：当前模型、生成中、模型未连接或记忆处理中。

右侧：

- 记忆；
- 角色资料；
- 更多。

规则：

- 高频入口最多 2 个加“更多”，不能排满一整行小图标；
- 模型状态使用真实状态，不用“API 已配置”冒充“模型已连接”；
- 记忆启用时可显示小状态点，但必须同时有文字或 tooltip；
- 窄屏保留返回、头像、名称、一个关键状态和“更多”。

### 5.3 消息区

Telegram 7.0.8 的消息内容内边距约为 `11px 8px`，大气泡圆角为 `16px`，消息时间为 `13px`。Leslie 采用：

- 气泡圆角：`16px`；连续消息可弱化相邻角；
- 气泡内边距：横向 `11–12px`，纵向 `8–9px`；
- 聊天正文：`15px`，行高 `1.55–1.65`；
- 时间、Swipe 计数和辅助状态：`12px`；
- 桌面气泡最大宽度：`min(76%, 780px)`；
- 手机气泡最大宽度：`90%`；
- 同一发送者连续消息减少重复头像、名字和垂直空白；
- 系统信息居中显示为轻量状态胶囊，不伪装成角色消息；
- 长篇角色扮演回复仍保留 Markdown、代码、图片、音频和扩展渲染能力。

气泡阴影应极弱或取消。深色模式优先通过底色差区分消息；浅色模式允许 `1px` 以内的边界或轻微阴影，不能同时使用粗描边和重阴影。

#### Swipe

Swipe 是同一轮回复的候选版本切换：

- 计数放在消息底部辅助区；
- 左右按钮默认弱化，悬停、焦点或触摸时显示；
- 手机上保留现有按钮与手势兼容；
- 不修改 Swipe 数据结构、生成流程或聊天 JSONL。

#### 生成状态

- 流式生成时只更新当前消息和头部状态；
- 停止按钮占用原发送按钮位置，避免布局横跳；
- 失败状态贴近失败消息，提供“重试”与“查看原因”；
- 全局 toast 只做补充，不用来替代消息内错误。

### 5.4 输入区

Telegram 7.0.8 的输入字段最小高度为 `36px`，附件按钮高 `46px`，发送区约 `44×46px`。Leslie 推荐：

- 整体最小高度 `52px`，外边距 `8–12px`；
- 输入字段最小 `36px`，随内容增长，桌面上限约 `224px`；
- 附件、快捷指令、发送/停止的视觉按钮为 `40–44px`；
- 输入容器圆角 `18px`，不是独立巨型卡片；
- 主要操作只保留一个蓝色发送/停止按钮；
- 错误、未连接和上下文超限显示在输入区上方，附带可执行入口；
- Enter 发送和换行继续服从 SillyTavern 现有设置。

输入区不能承载大量永久可见的模型参数。低频控制放入“更多”或设置，原入口继续保留。

### 5.5 角色记忆

角色记忆是聊天上下文详情，桌面优先使用第三栏或主从页面；中等窗口可以使用居中工作区；手机占满视口。

结构：

1. 顶部：角色名、记忆总状态、是否参与回复；
2. 一级页签：记忆事件、角色成长、互动关系（实验性）、设置与安全；
3. 内容列表：标题、摘要、类别、来源、状态；
4. 详情：来源消息、可信度、是否进入提示词、历史版本和恢复操作。

规则：

- A/B/C 类别必须有文字标签，不能只靠颜色；
- “互动关系”默认关闭并显示明确的实验性标签；初版只在单角色聊天开放，统一展示好感、信任、亲密、默契、安全感和羁绊六条 0–100 数值；
- 关系面板需要区分 A/B 长期基础与会衰减的 C 类近期影响，并为每次变化显示来源记忆、方向和理由；
- 关系开关只决定态度状态是否参与回复，不得关闭、删除或改写 A/B/C 记忆；旧记忆的 API 转换必须说明只发送摘要而非完整聊天；
- “参与回复”是重要开关，旁边说明影响范围；
- “尚未载入”“分析失败”“存储路径错误”分别展示，不能统一写成“出错了”；
- 存储错误在记忆页内显示常驻错误条，同时只弹一次简短 toast；
- 危险操作使用红色文字和确认步骤，不把整张卡片涂红；
- 互动关系使用独立提示词和版本化关系字段，不改写原始角色卡；关闭实验开关时，原有记忆注入内容和顺序保持不变。

### 5.6 设置

设置继续采用现有主从结构，但视觉从“卡片看板”收紧为“分组列表”。

桌面：

- 左栏沿用会话栏宽度；
- 右栏内容最大阅读宽度 `760–840px`，在可用区域内居中；
- 分类标题 `12px / 600`，使用次要文字色；
- 普通设置行 `52–56px`；
- 同组设置共享一个容器，行与行之间用缩进分隔线；
- 不为每个设置项单独加描边、圆角和阴影。

模型连接页：

- 先选择“联网模型服务”或“本地模型服务”；
- 再以紧凑列表选择供应商；
- 每行结构为图标、名称、简述、右侧选中状态；
- 地址、密钥、模型和连接按钮是默认可见的核心字段；
- 其他参数折叠到“高级选项”；
- 清楚区分“未配置”“已保存”“连接中”“已连接”“连接失败”。

手机：先显示设置分类，点击后进入详情页；返回回到分类，不把桌面双栏压缩进一屏。

### 5.7 AI 角色工坊

角色工坊可以比聊天界面更像“任务工作区”，但仍使用同一套设计语言。

- 桌面顶部 `56–60px`；
- 步骤栏推荐 `260–280px`；
- 正文最大宽度 `840px`；
- 底部操作栏 `60–68px`；
- 每一步只突出一个主要按钮；
- 大标题桌面不超过 `32px`，手机不超过 `28px`；
- 连续表单使用段落和分隔线组织，不为每个字段套卡片；
- 结果中的“正文、示例对话、边界、头像提示词”等可折叠，但展开后必须可搜索、复制和键盘操作；
- 草稿未保存、只在内存中、将带入原编辑器等状态放在底部操作附近。

现有五步流程可以保留。后续只整理视觉密度，不改变角色生成、审校、JSON 导入或保存边界。

### 5.8 弹出菜单、模态框和 toast

| 元素 | 推荐规则 |
| --- | --- |
| 菜单 | 圆角 `8–10px`，行高 `40px`，轻阴影，靠近触发按钮 |
| 普通确认框 | 圆角 `14–16px`，最大宽度 `440px` |
| 大型工作区 | 优先主从页或第三栏；确需模态时最大化利用视口 |
| toast | 最大宽度 `360px`，标题一行、说明最多两行，`4–6s` 后消失 |
| 常驻错误 | 放在所属页面内容顶部，提供修复动作，不自动消失 |

当前截图中的存储错误 toast 面积过大且遮挡关键内容。目标是缩短文案并靠右上显示，例如：

```text
角色记忆未加载
存储目录配置不完整。查看修复方法
```

完整技术信息放入“详情”或日志，不直接堆在主界面。

## 6. 质感核心：材质、颜色与表面层级

这一节是本规范最重要的视觉基线。这里的“材质”不是模拟真实玻璃、金属或皮革，而是界面通过底色、透明度、边界、模糊和阴影形成的触感与层次。

Leslie 的目标材质是：

> 哑光深蓝灰底、干净白色表面、少量半透明浮层、克制的蓝色高光。整体像一张安静、结实的桌面工作台，而不是一组发光的游戏面板。

质感主要来自相邻颜色之间稳定而细微的明暗关系，不来自给每个元素增加渐变、描边和阴影。

### 6.1 五层表面系统

所有页面只使用以下五类表面。开发时先判断元素属于哪一层，再决定颜色和阴影，不能为单个页面随意发明新材质。

| 层级 | 名称 | 典型对象 | 材质规则 |
| --- | --- | --- | --- |
| L0 | 画布 | 应用最底层、聊天背景 | 无圆角、无阴影；允许极弱纹理 |
| L1 | 主平面 | 会话栏、聊天头部、设置页面 | 不悬浮；依靠底色和 `1px` 分隔线区分 |
| L2 | 分组表面 | 设置分组、输入框、信息区块 | 圆角 `10–12px`；无阴影或只有内侧高光 |
| L3 | 浮动表面 | 菜单、toast、日期标签、滚动按钮 | 圆角 `8–12px`；轻阴影；可使用有限透明度 |
| L4 | 聚焦层 | 模态框、大型工作区 | 圆角 `14–18px`；清晰遮罩和单层阴影 |

关键限制：

- 同一个元素不能同时表现为多个层级；
- 普通列表行属于 L1，不得做成 L3 悬浮卡片；
- 同一视图最多出现两层明显悬浮关系，例如“页面 + 菜单”，不能“页面 + 大卡片 + 小卡片 + 发光按钮”；
- L0 和 L1 负责绝大部分面积，L3 和 L4 只能占少量区域；
- 圆角与阴影的强度必须随层级增加，不能倒置。

### 6.2 深色主题材质配方

当前项目深色主题的 `#09111b`、`#101a27`、`#152131` 整体偏黑，相邻区域又过于接近；加上大量描边后容易出现“黑色塑料盒子堆在一起”的感觉。

推荐改为更接近 Telegram Night 的石墨蓝灰关系：

| 角色 | 推荐颜色 | 视觉作用 |
| --- | --- | --- |
| L0 应用/聊天画布 | `#0e1621` | 最深背景，只在聊天和窗口边缘出现 |
| L1 会话栏/主表面 | `#17212b` | 主体哑光蓝灰，不使用纯黑 |
| L2 分组/收到气泡 | `#182533` | 比主表面略亮并略偏蓝 |
| L2 强分组 | `#1c2937` | 表单组、折叠区展开内容 |
| Hover | `#202b36` | 短暂悬停，不加描边 |
| Raised / 菜单 | `#223043` | 浮动层，比下面表面亮一档 |
| Active / 发出气泡 | `#2b5278` | 选中和用户消息，避免到处使用 |
| 主文字 | `#f5f5f5` | 不使用发蓝的纯白 |
| 次文字 | `#9aabba` | 摘要和说明，保证可读性 |
| 第三文字 | `#7f91a4` | 时间、占位符和低优先级元数据 |
| 分隔线 | `rgba(255,255,255,.075)` | 只建立边界，不形成白框 |
| 内侧高光 | `rgba(255,255,255,.035)` | 仅用于 L2/L3 顶缘或选中控件 |

深色主题面积比例：

- 约 `70%` 使用 L0/L1；
- 约 `24%` 使用 L2 和气泡；
- 不超过 `6%` 使用蓝色、警告色和错误色。

深色主题禁止：

- 使用 `#000000` 作为大面积应用背景；
- 为每张卡片画明显灰白边框；
- 同时使用亮边框、蓝色发光和重阴影；
- 用高饱和渐变填充普通图标底座；
- 把次要文字压暗到难以阅读，再用更亮边框补层级。

### 6.3 浅色主题材质配方

浅色主题的质感来自“白色工作平面 + 轻雾蓝画布 + 清晰文字”，不是所有区域都变成灰色卡片。

| 角色 | 推荐颜色 | 视觉作用 |
| --- | --- | --- |
| L0 应用/聊天画布 | `#e9eff5` | 冷静的雾蓝灰背景 |
| L1 会话栏/主表面 | `#ffffff` | 干净主平面 |
| L2 分组表面 | `#f6f8fa` | 输入、设置分组和次级内容 |
| Hover | `#f1f3f5` | 列表悬停 |
| Raised / 菜单 | `#ffffff` | 浮层保持清洁白色 |
| Active | `#e7f2fd` | 当前会话和选中项 |
| 发出气泡 | `#def1fd` | 低饱和浅蓝 |
| 主文字 | `#17212b` | 深蓝黑，比纯黑柔和 |
| 次文字 | `#5f7184` | 摘要和说明 |
| 第三文字 | `#657688` | 时间和低优先级元数据；仍保持正文级可读性 |
| 分隔线 | `rgba(23,33,43,.10)` | 细而稳定的边界 |
| 内侧高光 | `rgba(255,255,255,.72)` | 只用于蓝色控件或浮层顶缘 |

浅色主题不要在整个页面铺大面积淡蓝渐变。蓝色应该出现在当前会话、主按钮、链接和焦点，而不是把所有容器都染蓝。

### 6.4 强调色的完整状态

不能只定义一个蓝色，然后让浏览器自动推导所有状态。主要强调色必须形成可预测的一组：

| 状态 | 浅色主题 | 深色主题 |
| --- | --- | --- |
| 默认 | `#3390ec` | `#4aa8ff` |
| 悬停 | `#2b82d9` | `#63b5ff` |
| 按下 | `#2475c6` | `#378fd7` |
| 柔和底色 | `rgba(51,144,236,.12)` | `rgba(74,168,255,.14)` |
| 焦点环 | `rgba(51,144,236,.34)` | `rgba(74,168,255,.42)` |
| 禁用 | 主色与表面混合至约 `45%` | 主色与表面混合至约 `42%` |

品牌蓝只用于：

- 主操作；
- 当前选中项；
- 可点击链接；
- 键盘焦点；
- 在线、生成或同步等确实需要关注的活动状态。

品牌蓝不用于普通说明文字、所有图标背景、每张设置卡片的边框或大面积页面渐变。

### 6.5 透明、玻璃和模糊

Telegram 当前产品宣传素材包含玻璃感界面，但 Telegram Desktop Windows 的日常主界面仍以稳定实色平面为主。Leslie 只在以下位置使用有限玻璃材质：

- Electron 自定义标题栏；
- 覆盖聊天背景的顶部栏；
- toast、日期标签和小型浮动控制；
- 模态框背后的遮罩。

推荐深色玻璃配方：

```css
background: rgba(23, 33, 43, 0.84);
border: 1px solid rgba(255, 255, 255, 0.08);
box-shadow: 0 8px 24px rgba(0, 0, 0, 0.24);
backdrop-filter: blur(18px) saturate(1.12);
```

推荐浅色玻璃配方：

```css
background: rgba(255, 255, 255, 0.86);
border: 1px solid rgba(23, 33, 43, 0.08);
box-shadow: 0 8px 24px rgba(31, 56, 88, 0.14);
backdrop-filter: blur(18px) saturate(1.08);
```

使用条件：

- 下方确实存在可见图片、纹理或滚动内容时才有必要模糊；
- 纯色背景上的透明卡片没有材质价值，改用实色；
- 长列表和整个设置页禁止全屏 `backdrop-filter`，避免显卡负担和文字发灰；
- 必须提供不支持模糊时的实色回退；
- 同一屏幕最多一类主要玻璃表面。

### 6.6 聊天画布纹理

Telegram 的聊天质感有一部分来自低对比度背景图案。Leslie 可以保留用户自定义背景，并为默认主题增加极弱的自有纹理，但不能复制 Telegram 的涂鸦图案。

默认纹理方向：

- 题材使用抽象书页、星点、对话符号或 Leslie 自有记忆符号；
- 单色，深色主题使用浅色纹理，浅色主题使用深色纹理；
- 正常不透明度 `2–3%`，最多 `4%`；
- 图案尺寸建议 `160–240px`，避免密集重复和摩尔纹；
- 消息密集区域不能影响文字识别；
- 用户选择自定义背景后，默认纹理关闭；
- 背景较亮或复杂时自动增加一层画布遮罩。

可选的微噪点只能使用单色、小尺寸、低于 `1.5%` 的静态纹理。不要使用动态噪点、闪烁粒子或大面积渐变动画。

### 6.7 四种标准材质组件

#### A. 连续列表

用于会话、设置分类、记忆事件：

- 背景继承 L1；
- 默认无圆角、无阴影、无外边框；
- Hover 只改底色；
- Active 使用柔和蓝底，可加 `3px` 以内侧状态线；
- 分隔线从正文起点开始，不穿过头像。

#### B. 分组容器

用于一组相关设置或表单：

- L2 实色背景；
- `1px` 低对比度边界；
- 圆角 `12px`；
- 容器内各行共享外框，不各自套卡；
- 无外部阴影，可选极弱内侧高光。

#### C. 浮动菜单

- L3 表面；
- 圆角 `10px`；
- `1px` 低对比度边界；
- 轻阴影；
- 菜单行高 `40px`；
- 危险项只让图标和文字变红，不染红整张菜单。

#### D. 聚焦工作区

用于角色工坊和确需模态的大型工具：

- L4 实色表面，不做全透明玻璃盒；
- 圆角 `16px`；
- 单层外部阴影；
- 内部继续使用连续列表和分组容器，禁止层层嵌套悬浮卡片；
- 手机端去掉外圆角和阴影，直接占满视口。

### 6.8 质感禁用清单

以下组合是当前项目最容易导致“没有质感”的原因，后续默认禁止：

- 每个列表项都是圆角卡片；
- 每张卡片同时存在渐变、描边和阴影；
- 深色背景上铺多层接近黑色但关系不明的蓝灰；
- 用 `20–28px` 圆角包所有区域；
- 普通工作区使用 `0 30px 100px` 级别重阴影；
- 每个图标都放进不同颜色的渐变方块；
- 大面积蓝绿渐变作为普通表单背景；
- 透明表面下面没有可被看见的内容；
- 为显示层级不断增加外框，而不是调整底色和留白；
- 一个界面中同时出现玻璃、霓虹、拟物和扁平四种材质。

材质自检方法：把截图转成灰度后，主画布、主平面、分组和浮层仍应能清楚区分；如果只能靠蓝色边框看出层级，说明材质关系没有建立好。

### 6.9 设计令牌

设计令牌是“一组有语义名称的颜色、尺寸和间距变量”。后续组件只引用语义变量，避免聊天、设置和角色工坊各自维护一套近似颜色。

推荐建立以下统一变量。数值保留 Telegram 的中性深蓝灰方向，但继续使用 Leslie 自有命名和品牌。

| 变量 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--leslie-bg-app` | `#e9eff5` | `#0e1621` | 应用外层与聊天背景基底 |
| `--leslie-bg-sidebar` | `#ffffff` | `#17212b` | 会话栏 |
| `--leslie-bg-surface` | `#ffffff` | `#17212b` | 头部、菜单、输入区 |
| `--leslie-bg-subtle` | `#f6f8fa` | `#182533` | 次级区块、对方气泡 |
| `--leslie-bg-hover` | `#f1f3f5` | `#202b36` | 悬停 |
| `--leslie-bg-raised` | `#ffffff` | `#223043` | 菜单、toast 等浮动表面 |
| `--leslie-bg-active` | `#e7f2fd` | `#2b5278` | 选中会话或选项 |
| `--leslie-text-primary` | `#17212b` | `#f5f5f5` | 主文字 |
| `--leslie-text-secondary` | `#5f7184` | `#9aabba` | 摘要和说明 |
| `--leslie-text-tertiary` | `#657688` | `#7f91a4` | 时间、占位符 |
| `--leslie-border-subtle` | `rgba(23,33,43,.10)` | `rgba(255,255,255,.08)` | 分隔线 |
| `--leslie-accent` | `#3390ec` | `#4aa8ff` | 主要操作、链接、焦点 |
| `--leslie-accent-soft` | `rgba(51,144,236,.12)` | `rgba(74,168,255,.14)` | 选中和轻提示 |
| `--leslie-bubble-in` | `#ffffff` | `#182533` | 角色/对方消息 |
| `--leslie-bubble-out` | `#def1fd` | `#2b5278` | 用户消息 |
| `--leslie-success` | `#2fa36b` | `#49c98b` | 已连接、成功 |
| `--leslie-warning` | `#c88719` | `#e2a93b` | 已配置未连接、待确认 |
| `--leslie-danger` | `#d84a4a` | `#ff6b6b` | 失败和危险操作 |
| `--leslie-overlay` | `rgba(15,23,42,.34)` | `rgba(0,0,0,.52)` | 模态遮罩 |

Telegram 7.0.8 夜间主题的关键原值包括 `#17212b` 背景、`#202b36` 悬停、`#2b5278` 当前会话和发出气泡、`#182533` 收到气泡。上表将这些关系作为依据，但不是要求所有页面原样使用 Telegram 主题文件。

### 6.10 现有变量迁移

当前项目同时存在 `--leslie-*`、`--leslie-shell-*` 和 `--workshop-*`。后续不要一次性全局替换；先建立别名，再逐文件迁移：

```css
:root {
    --leslie-shell-bg: var(--leslie-bg-app);
    --leslie-sidebar-bg: var(--leslie-bg-sidebar);
    --leslie-shell-surface: var(--leslie-bg-surface);
    --leslie-shell-surface-soft: var(--leslie-bg-subtle);
    --leslie-shell-hover: var(--leslie-bg-hover);
    --leslie-shell-active: var(--leslie-bg-active);
    --leslie-shell-text: var(--leslie-text-primary);
    --leslie-shell-muted: var(--leslie-text-secondary);
    --leslie-shell-border: var(--leslie-border-subtle);
}
```

这样可以小步撤回，也能避免一次改动三份大型 CSS 导致回归。

### 6.11 字体与文字层级

不要求下载额外网络字体，优先使用系统字体：

```css
font-family: system-ui, "Segoe UI", "Microsoft YaHei UI",
    "PingFang SC", "Noto Sans CJK SC", sans-serif;
```

| 用途 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面大标题 | `28–32px / 1.2` | `700` |
| 页面标题 | `20–24px / 1.3` | `650–700` |
| 会话名、区块标题 | `15–16px / 1.35` | `600` |
| 聊天正文 | `15px / 1.55–1.65` | `400` |
| 普通界面正文 | `14px / 1.5` | `400` |
| 说明、时间、状态 | `12px / 1.4` | `400–600` |

英文大写小标签只用于极少量品牌或版本信息。普通中文界面不要用大段全大写英文制造层级。

### 6.12 间距

以 `4px` 为基础网格：

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`

- 图标与文字：`8–12px`；
- 同一字段内：`4–8px`；
- 同组设置：`0–4px` 加分隔线；
- 不同区块：`16–24px`；
- 页面边距：手机 `16px`，桌面 `20–24px`；
- 大型工作区正文左右留白不超过 `48px`，避免浪费空间。

### 6.13 圆角

| 对象 | 圆角 |
| --- | ---: |
| 消息气泡 | `16px` |
| 搜索与输入容器 | `18px` |
| 按钮、菜单、设置分组 | `8–12px` |
| 模态框和大型工作区 | `14–18px` |
| 状态徽标 | 胶囊或 `999px` |
| 头像 | 圆形 |

避免把 `20–28px` 大圆角用于所有页面、卡片和输入框。大圆角应该是少数高层容器的特征，不是默认装饰。

### 6.14 阴影与边框

- 普通页面区块：无阴影；
- 会话、设置行和气泡：底色、轻边框二选一；
- 菜单：`0 8px 24px rgba(15, 30, 49, .18)`；
- 模态框：`0 18px 48px rgba(15, 30, 49, .24)`；
- 深色模式阴影更透明，主要依赖底色差；
- 移除普通工作区现有的 `30px 100px` 级重阴影。

### 6.15 图标

- 使用一套一致的线性或填充体系，不混用多套视觉重量；
- 常用图标画布 `20–22px`，桌面按钮 `40px`；
- 状态小图标 `14–16px`；
- 每个纯图标按钮都有中文 tooltip 和 `aria-label`；
- Leslie 自行设计记忆、角色、World Info 和模型图标；
- 禁止复制 Telegram 纸飞机、官方图标文件或商标。

## 7. 颜色与状态规则

### 7.1 模型连接

| 状态 | 颜色 | 推荐文案 |
| --- | --- | --- |
| 未配置 | 次要灰 | “尚未配置模型” |
| 已保存未连接 | 警告色 | “已配置，尚未连接” |
| 连接中 | 蓝色 + 进度 | “正在连接…” |
| 已连接 | 成功色 | “已连接 · 模型名” |
| 失败 | 错误色 | “连接失败 · 重试” |

### 7.2 Leslie 记忆

| 状态 | 表达 |
| --- | --- |
| 未加载 | 灰点 + “记忆尚未加载” |
| 已加载但不参与回复 | 灰点 + “记忆已暂停” |
| 正常参与 | 蓝/绿点 + “记忆参与回复” |
| 分析中 | 进度动画 + “正在整理记忆” |
| 待审核 | 警告点 + 数量 |
| 失败 | 红点 + “记忆处理失败”及修复入口 |

颜色从不单独承担含义，必须同时有文字、图标形状或数量。

### 7.3 危险操作

删除角色、删除聊天、清理记忆、重置设置等操作：

- 列表入口使用普通文字；进入确认步骤后才使用红色；
- 确认框写清删除对象、影响和恢复方法；
- 可以恢复的操作优先进入回收站或历史版本；
- 不静默改变或删除聊天、角色卡、记忆与 API 密钥。

## 8. 动效与反馈

Telegram 7.0.8 会话状态和滚动按钮常用 `150ms`，面板常用约 `200ms`。Leslie 采用：

- 悬停、按压、焦点：`120–150ms`；
- 菜单、toast：`150–180ms`；
- 页面、详情栏、模态框：`180–220ms`；
- 使用 `opacity` 与 `transform`，避免对宽高做昂贵长动画；
- 发送和流式生成不让整页跳动；
- 遵循 `prefers-reduced-motion`，关闭不必要位移和缩放；
- 动效只解释状态变化，不作为持续装饰。

## 9. 可访问性

- 正文与背景对比度至少达到 WCAG AA，普通文字推荐不低于 `4.5:1`；
- 键盘可以进入会话列表、头部操作、消息操作、输入区、设置和模态框；
- 焦点环使用 `2px` 强调色并与元素保持间隙；
- 手机触控目标不小于 `44×44px`；
- `125%–150%` 缩放时头像、名称、时间、未读数不能重叠；
- 只显示图标的按钮必须有可读名称；
- 模态框打开后管理焦点，关闭后回到原触发按钮；
- 状态不能只靠颜色区分；
- 长消息、代码块和 JSON 区域必须可选择、可复制，并有独立滚动边界。

## 10. SillyTavern 功能映射

| 现有能力 | Leslie 位置 | 保留方式 |
| --- | --- | --- |
| 角色与最近会话 | 左侧会话列表 | 列表只呈现并触发原选择逻辑 |
| 新建聊天 | 聊天头部“＋” | 按当前世界线新建，不因选择角色自动新建 |
| 角色卡 | 聊天头部“角色资料” | 打开详情栏或原编辑页 |
| Leslie 记忆 | 聊天头部“记忆” | 第三栏、主从页或移动全屏页 |
| World Info | 聊天头部“更多”与详情 | 保留原功能和数据 |
| 模型连接 | 头部状态、输入区提示、设置 | 复用原连接与密钥保存逻辑 |
| Swipe | AI 消息底部 | 原事件和数据结构不变 |
| 编辑、删除、重新生成 | 消息悬停/更多菜单 | 复用原事件 |
| 群聊 | 会话列表与聊天头部 | 原群聊流程不变 |
| Prompt Manager、扩展、高级参数 | 设置中的高级模式 | 降低默认优先级，不删除 |

## 11. 实现边界

### 11.1 可以改变

- CSS 变量、颜色、间距、圆角、阴影和响应式布局；
- 现有页面区域的顺序、分组和视觉层级；
- 为已有功能增加新的表现层入口或包装容器；
- 默认隐藏低频高级控件，只要能从高级模式恢复；
- 新增只保存界面偏好的本地设置；
- 在不改变数据的前提下增加第三栏、主从页和移动页面导航。

### 11.2 不得改变

- SillyTavern 消息请求和提示词拼装顺序；
- 角色卡、聊天 JSONL、World Info、群聊和 Swipe 数据格式；
- API 密钥保存方式和模型适配层；
- Leslie 记忆注入内容、顺序和存储格式；
- 为了“简化”而删除原 DOM、事件或高级功能；
- 把同步状态或未来局域网模块接入回复生成流程。

### 11.3 推荐实现方式

- 继续保留原元素 `id`、事件和数据来源；
- 优先新增外层布局、CSS 类和轻量适配，不复制聊天引擎；
- 先统一设计令牌，再逐页改组件；
- 每一页单独改、单独截图、单独回归；
- 旧版布局按钮已移除；必要的上游功能通过 Leslie 入口触发原事件；
- 修改启动方式后继续核对 `Using data root`，本设计不改变固定数据路径。

## 12. 与当前原型的差距

### 已经符合

- 桌面双栏与移动单栏方向；
- 角色/最近会话入口；
- 聊天头部、更多菜单和底部输入区；
- 设置主从结构；
- 角色记忆与角色工坊作为隔离工作区；
- 深浅主题基础。

### 优先收紧

1. **卡片过多。** 会话、设置选项、供应商和工具步骤大量各自带背景、描边和圆角；应改成连续列表与分组容器。
2. **圆角过大。** 多处使用 `20–28px`；应收敛到 `8 / 12 / 16 / 18px` 四档。
3. **阴影过重。** 普通工作区不应使用大范围深阴影。
4. **设计变量重复。** `--leslie-*`、`--leslie-shell-*`、`--workshop-*` 需要通过别名逐步统一。
5. **状态提示遮挡。** 记忆存储错误 toast 过大，应变成小 toast 加页面内常驻错误。
6. **设置页密度偏低。** 大块供应商卡片在小窗口滚动距离过长，应改为紧凑列表。
7. **角色工坊标题和容器偏大。** 保留流程，缩小标题与卡片层级。

这些是后续视觉收口项，不应绕过 `roadmap.md` 中的数据保护、回归测试和稳定化工作。完成原型收口前，不启动大规模 UI 重构。

## 13. 推荐实施顺序

### 阶段 0：只统一令牌

- 新增统一语义变量；
- 用别名兼容现有变量；
- 不改 DOM，不改功能；
- 截图对比深浅主题。

### 阶段 1：主聊天减法

- 会话行改为连续列表；
- 收紧头部、搜索、底部状态和输入区；
- 减少描边、圆角和阴影；
- 回归发送、停止、Swipe、编辑、删除、重新生成和最近会话。

### 阶段 2：消息与详情

- 统一气泡、系统消息、流式生成与错误；
- 宽窗口加入按需第三栏；
- 接入角色资料、记忆和 World Info；
- 不改底层功能。

### 阶段 3：设置、记忆、角色工坊

- 设置卡片改分组列表；
- 记忆状态与错误重新分层；
- 角色工坊保留五步流程，收紧标题、表单和底部操作。

### 阶段 4：移动端和可访问性

- 完成 `<700px` 页面式导航；
- 修复记忆入口可见性；
- 验证键盘、焦点、缩放、读屏标签和减少动画。

每阶段都不得迁移或修改正式用户数据；经典设计语言仍可独立选择。

## 14. 验收清单

### 视觉

- [ ] 会话列表不再由一排独立大卡片组成；
- [ ] 普通会话行约 `64px`，头像约 `48px`；
- [ ] 消息气泡主圆角统一为 `16px`；
- [ ] 搜索和输入容器圆角约 `18px`；
- [ ] 同一页面最多一个主强调色；
- [ ] 普通内容区无重阴影；
- [ ] 深浅主题都能分清背景、悬停、选中和焦点；
- [ ] 设置、记忆和角色工坊看起来属于同一产品。

### 行为

- [ ] 选择联系人继续最近会话，不意外创建聊天；
- [ ] 发送、停止、编辑、删除、重新生成和 Swipe 正常；
- [ ] 角色卡、记忆、World Info 和高级模式可进入；
- [ ] 模型状态真实区分未配置、未连接、已连接和失败；
- [ ] 记忆错误不会遮挡主要操作；
- [ ] 第三栏打开和关闭不丢输入草稿或滚动位置；
- [ ] `<700px` 列表、聊天和设置可以正常返回；
- [ ] 经典设计语言可切换，且原有聊天功能仍可用。

### 测试尺寸

- [ ] `1440×900`：桌面三栏能力；
- [ ] `1024×768`：标准双栏；
- [ ] `800×600`：紧凑双栏；
- [ ] `390×844`：手机单栏；
- [ ] Windows `125%` 和 `150%` 缩放；
- [ ] 深色、浅色和自定义强调色；
- [ ] 键盘与减少动画模式。

## 15. 最终原则

后续评审一个界面是否符合本规范，可以依次问：

1. 当前任务最重要的内容是否第一眼可见？
2. 去掉这张卡片、这条描边或这层阴影，层级是否仍然清楚？
3. 状态是否贴近它影响的角色、消息、模型或记忆？
4. 常用操作是否直接，高级操作是否仍可访问？
5. 是否只改表现层，没有破坏 SillyTavern 原能力和用户数据？

如果五个答案都是“是”，它就符合 Leslie 所需要的 Telegram 式设计：快、清楚、安静，并把注意力留给角色和对话。
