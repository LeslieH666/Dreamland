# DreamLand 前后端分离重构方案（核心聊天版）

> 目标：把当前“单进程一体化”的 DreamLand（SillyTavern 衍生）重构为**前后端分离**的产品：
> - 后端部署在 **Linux 服务器**（公有 SaaS，多租户），**仅代理云端 API**；
> - 前端为 **React Native 跨平台 App**（iOS/Android，后期渐近转原生）+ **Web 端**；
> - **一份代码库同时产出「服务器版」与「桌面版」**（一举两得）；
> - 功能范围收敛为**核心聊天**：砍掉 AIRI、本地模型部署等“服务器上不好运营”的能力。
>
> 已确认决策：
> 1. **多租户 SaaS**（你运营一个后端，服务所有注册用户）。
> 2. **仅代理云端 API**（OpenAI/DeepSeek/火山等）；**砍掉**本地模型部署（GGUF/KoboldCpp/llama.cpp）与 **AIRI**。
> 3. 移动端 **React Native 先行**，后期按模块逐步替换为 Swift/Kotlin 原生。
> 4. **保留桌面端**，采用“一份代码、两种打包”的方式同时维护服务器版与桌面版。

## 1. 现状架构（结论）

DreamLand 是一个 **Node.js/Express 单进程单体**，同一进程承担三件事：

```text
┌─────────────────────────────────────────────────────────────┐
│  Electron 壳（src/electron）— 托盘/退出/AIRI与本地模型启停   │
└────────────────────────────┬────────────────────────────────┘
                             │ IPC
┌────────────────────────────▼────────────────────────────────┐
│  Express 单体（src/server-main.js）                          │
│   ① 托管前端：public/ index.html(738KB)+script.js(507KB)     │
│      + ~130 个 jQuery 脚本 + webpack 实时编译                │
│   ② 全部后端 API：~50 个 endpoint + Leslie 模块             │
│   ③ 认证：cookie-session(内存)+CSRF+IP白名单+账户            │
└──────────────┬──────────────────────────────────────────────┘
               │ SSE 流式（fetch + ReadableStream，非 WebSocket）
        ┌──────┴──────────┐
        │ 数据层（全文件式）│ JSONL 聊天 / PNG 角色卡 / node-persist 账户
        └─────────────────┘ vectra 向量记忆 / 上传 / 可选 AES 加密空间
```

关键事实：
- **后端核心与前端 UI 已在同一个仓库里**，只是耦合方式（同源 Cookie + 相对路径）不适合公网 App 接入。
- **已有“干净 API 种子”**：`/api/leslie/bridge/v1`（Bearer token、能力发现、OpenAI 兼容 SSE 流式聊天、火山语音，且有 OpenAPI 契约 `docs/contracts/`）。这是最小重构要复用的资产。
- **Electron 壳本就是薄封装**：它启动同一个 `server.js`，只额外加了托盘/退出/IPC 等桌面能力。这正是“一份代码、两种打包”能成立的基础。

## 2. 目标架构：一份代码 → 三个产物

```text
               ┌──────────────────────────────────────────────┐
               │          同一份代码库（monorepo）             │
               ├──────────────────────────────────────────────┤
               │ ① 后端核心（平台无关、纯 Node）               │
               │    Express + SillyTavern 聊天引擎 + Leslie 模块│
               │    + 公共 API v1 + 账户/认证 + 云端模型适配器  │
               ├──────────────────────────────────────────────┤
               │ ② Web 前端（public/，PWA 化）                 │
               │    服务器版与桌面版共用同一套界面              │
               ├──────────────────────────────────────────────┤
               │ ③ React Native App（iOS/Android）            │
               │    只对接 ① 的公共 API                        │
               ├──────────────────────────────────────────────┤
               │ ④ 桌面宿主层（Electron，可选薄壳）            │
               │    托盘/自动启动/退出封存，仅桌面版使用        │
               └──────────────────────────────────────────────┘

打包目标（同一源码，不同裁剪）：
  · 服务器版 = ① + ②              → Linux 容器（无 Electron）
  · 桌面版   = ① + ② + ④          → Electron 安装包（同一后端核心）
  · 移动版   = ③                   → iOS/Android App（只连 ① 的 API）
```

**核心原则**：SillyTavern 聊天引擎 + Leslie 聊天侧模块**原样保留为后端核心**；在它们外面加「公共 API + 新认证」，前端/App 变成独立客户端。桌面端只是给同一个后端核心套一层 Electron 薄壳，不是第二套代码。

## 3. “一举两得”：服务器版与桌面版共用一份代码

当前 Electron 壳已经是薄封装，所以“一份代码、两种运行形态”**不需要重写，只需要把边界理干净**：

1. **后端核心平台无关化**：把只属于桌面的逻辑从后端核心里挪到「桌面宿主层」，或加运行环境开关。具体是——
   - DPAPI/本地密钥文件：抽象成「密钥存储接口」——服务器版注入服务端加密(KMS/环境变量)，桌面版注入本地加密(DPAPI)。核心代码不变，只换实现。
   - 本地模型启停 / AIRI 控制：**砍掉**（见 §6），桌面版不再有这些入口。
   - 浏览器自动拉起 / 托盘 / 退出封存：属于 Electron 宿主层，不进服务器版。
   - 数据根：桌面版用本地目录，服务器版用容器卷/对象存储——同一套「存储接口」，两种实现。

2. **两个打包目标共用同一份 `public/` UI**：桌面版在 Electron 窗口里加载它，服务器版把它作为 Web/PWA 静态资源。前端改动一次，两端同时生效。

3. **认证双轨**：桌面版保留 cookie-session（本机使用体验好）；服务器版/App 走 JWT。两者共存于同一后端核心（迁移期双轨，见 §5 Phase 2）。

> 结论：桌面版不是“要额外维护的负担”，而是“同一后端核心的另一种发布形态”。这也是本项目天然适合前后端分离改造的原因。

## 4. 功能范围：只保留核心聊天

**保留**（服务器可良好运营、且属于聊天体验）：

- SillyTavern 聊天引擎、提示词组装、生成、持久化。
- 角色卡（CCV3 PNG）、JSONL 聊天、群聊、World Info、Swipe。
- 云端模型适配器（OpenAI / DeepSeek / 火山 / Anthropic / Google / OpenRouter / Horde 等，仅云端）。
- Leslie 聊天侧模块：身份(Persona/剧情线)、记忆、朋友圈、语音(TTS)、角色工坊、剧情选择/罗盘、群聊编排。

**砍掉**（服务器上不好运营）：

- **AIRI 桌面陪伴前端**（`airi/`）：从仓库剥离或归档，不再随产品维护。
- **本地模型部署/管理**（`src/leslie-local-model`、GGUF/KoboldCpp/llama.cpp 一键启停、`models/` 目录）：移除。
- **Electron 里的 AIRI 与本地模型启停控制**：随上面两项一并移除；Electron 壳本身保留（仅作桌面宿主）。

**可选下线的非聊天能力**（若“核心”要更窄，可再裁）：角色工坊的本地模型 provider（保留云端/DeepSeek）、朋友圈 AI 活动（可先关）。

## 5. 差距分析（现状 → 目标）

| 维度 | 现状 | 目标 | 性质 |
|------|------|------|------|
| 认证 | cookie-session + CSRF + IP 白名单 | JWT access/refresh + OAuth2；桌面版保留 cookie 双轨 | 替换（双轨迁移） |
| API | ~50 个无版本无契约 endpoint | `/api/v1/*` 版本化 + OpenAPI | 新增外壳，复用 handler |
| 密钥 | 每账户 secrets.json，Linux 明文 | 抽象接口：服务器版 KMS/环境变量，桌面版 DPAPI | 抽象 + 替换 |
| 数据 | 单根目录 + 客户端加密 vault | 抽象接口：服务器版对象存储+租户隔离，桌面版本地目录 | 抽象 |
| 会话/缓存 | 内存 cookie-session | 测试期单实例可接受；规模化前引 Redis | 延后 |
| 后台任务 | 进程内 setInterval | 测试期单实例可接受；规模化前引 BullMQ | 延后 |
| 部署 | 桌面/局域网假设 | 容器化 Linux + TLS + env 配置 | 替换 |
| 桌面专属 | AIRI/本地模型/DPAPI 混在后端 | 砍 AIRI/本地模型；DPAPI 抽成桌面注入实现 | 裁剪 + 抽象 |
| 前端 | 同源 jQuery SPA | Web PWA + React Native App | 解耦 |

## 6. 最小重构路线（分阶段）

### Phase 0 — 基线（约 1 周）
- `npm run validate` 全绿 + CI；划定「后端核心」边界并冻结（不重写）。
- 盘点全部 endpoint 生成 API 清单；建立自己的 Linux 镜像（修正现有镜像仍引用 SillyTavern 命名）。
- **裁剪**：从构建与运行时移除 AIRI 与本地模型相关代码/依赖，保证删干净且有测试兜底。

### Phase 1 — 后端可公网部署（约 2–3 周）
- 服务器启动去掉桌面假设：浏览器自动拉起、托盘、本地模型启停、LAN 白名单。
- 配置 12-factor 化：端口/数据根/密钥从环境变量读取。
- 容器化：Linux 基础镜像、非 root、`tini`、健康检查；TLS 交 Caddy/Nginx 反代。
- 数据持久化到卷 + 对象存储（角色卡/头像/语音）。

### Phase 2 — 公共 API v1 + Token 认证（约 3–4 周）★核心
- 把 `leslie-bridge` 泛化为 `/api/v1`（版本化 + OpenAPI + 统一错误/流式 SSE）。
- 新认证与旧 cookie-session **并行**：Web 桌面版继续用 cookie，App 用 JWT。
- 用适配器把现有 endpoint handler（characters/chats/groups/worldinfo/memory/moments/identity/tts/工坊/群聊编排）挂到 v1——**复用函数、不重写业务**。
- 密钥接口抽象：服务端加密托管（测试期可用环境变量/文件加密），客户端只见 key-id。
- 限流（`rate-limiter-flexible` 已在依赖）+ 每租户配额。

### Phase 3 — 桌面版“一举两得”落地（约 1–2 周，可与 P2 并行）
- 把 Electron 壳精简为纯「桌面宿主」：只保留托盘/自动启动/退出封存，移除 AIRI/本地模型控制。
- 建立两个打包目标：`server`（①+②，容器）与 `desktop`（①+②+④，Electron 安装包），共用同一源码与同一 `public/`。
- 密钥/存储接口在桌面版注入本地实现，在服务器版注入服务端实现。

### Phase 4 — Web 前端解耦（约 2 周，可与 P5 并行）
- Web UI 改为 PWA，桌面版沿用 Cookie、公网 Web 版走 Token；CSP/CORS 收紧。
- 按 roadmap 拆分 `public/scripts` 巨型模块。

### Phase 5 — React Native App（约 4–8 周）
- 基于 `/api/v1` 构建 App（见 §7）；停用现有 Android WebView/独立 Node Beta。
- 复用 `mobile/shared` 的地址/能力策略思路，改为对接公网 API。

### Phase 6 — 多租户、计费与运维（约 3–4 周，测试期可延后）
- 账户 → 租户；订阅/配额/用量计量。
- Redis 会话/缓存 + BullMQ 队列（迁出 Moments/记忆 worker）；热状态入 PostgreSQL。
- 可观测性、备份、密钥轮换。

## 7. 移动端策略：React Native 先行，渐近转原生

采用 **“RN 打底、按模块渐近原生化”** 的策略（strangler 模式）：

- **第一阶段（现在）**：用 React Native/Expo 交付完整 App，快速覆盖核心聊天 + 全量聊天功能。
- **第二阶段（后期）**：把性能/体验敏感的模块（流式渲染、音频、动画、未来 Live2D/口型）逐个用 Swift/Kotlin 原生重写，通过 RN 的原生模块/原生视图桥接，其余继续用 RN。

落地的两个关键架构约束（现在就要做对，否则后期迁移痛苦）：
1. **UI 与业务/网络彻底分层**：所有 API 调用走共享的「API 客户端 + 领域类型」层，与具体组件解耦。原生重写时只换 UI，网络/状态层零改动。
2. **按“功能模块”而非“页面”组织代码**：每个模块（聊天/角色/记忆/朋友圈/设置）边界清晰，原生迁移时可以整模块替换。

> 这样既满足“先用 RN 快速上线”，又为“后期转原生”留好退路，避免推倒重来。

## 9. 暂缓项（测试阶段不阻塞，商用前再处理）

> 你当前处于测试阶段、暂无商用需求，以下事项**现在不需要处理**，仅记录备查：

- **AGPL-3.0 源码提供义务**：正式对外提供网络服务时，需向用户提供可获取的完整源码（含修改）。测试/内部分发阶段可暂不处理。
- **iOS App Store 内容分级与审核**：正式上架前再处理 17+ 分级、年龄门控与审核策略；届时 iOS 若受限可用 Web PWA 兜底、Android 走官网分发。
- **计费/成本模型**：仅代理云端 API 每 token 有成本，正式运营前需用量计量 + 配额。
- **规模化改造**（Redis/BullMQ/PostgreSQL/对象存储）：单实例足以支撑测试期，到用户量上来再引入。

## 11. 一句话结论

> 保留 SillyTavern 聊天引擎与 Leslie 聊天侧模块作为**平台无关的后端核心**，用一层**版本化公共 API（从 Leslie Bridge v1 泛化）+ JWT/OAuth2 + 密钥/存储接口抽象**包起来；Web UI 与 React Native App 变成 API 的普通客户端；Electron 降级为“同一后端核心的桌面宿主薄壳”，从而用**一份代码同时产出服务器版和桌面版**。砍掉 AIRI 与本地模型后，重构范围显著缩小，测试期先以“单实例 + 后端 API 稳定 + RN App 上线”为目标，商用前再补计费、队列与合规。
