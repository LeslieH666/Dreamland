# DreamLand 上线前 —— 团队与 Agent 分工规划

> 适用阶段：从“测试/重构期”到“正式运营上线前”。配套文档：[frontend-backend-separation-plan.md](frontend-backend-separation-plan.md)（方案）、[refactor-execution-checklist.md](refactor-execution-checklist.md)（执行清单）。
>
> 目标：用**最小但完整的人手** + **AI Agent 作为杠杆**，把 P0–P5 稳定推进、聊天核心零回归，为上线做准备（P6 多租户/计费暂缓）。

---

## 1. 结论速览

- **推荐规模：5 人**（你 + 4 名工程师）。这是“舒适且可并行”的配置。
- **最小可跑：3 人**（你 + 后端 + 移动端），QA/前端由你 + Agent 分担，进度慢但能走通。
- **核心原则：**
  1. **后端 API 契约（P2）是全队阻塞点**，必须最早冻结；移动端工程师要**提前参与契约定义**（API-first），否则会空等。
  2. **QA/测试从 P0 就上**，因为“裁剪 AIRI/本地模型”最伤聊天核心兼容，必须有人专职守回归。
  3. **AI Agent 只做“可验证、可回退、机械”的活**（重构执行、测试生成、审查、审计、文档），**人做决策、验收、产品与安全红线把关**。

---

## 2. 角色分工（5 人推荐配置）

| # | 角色 | 负责区域 | 对应 Phase | 关键产出 | 与 Agent 的配合方式 |
|---|------|----------|-----------|----------|---------------------|
| 1 | **你 — 架构/产品负责人 & Agent 编导（Lead）** | 最终决策、产品方向、验收、数据红线守门；编排 Agent 任务并审报告 | 全程 | roadmap/决策记录、上线清单 | 你是 Agent 的“Team Lead”：给 Agent 派活、读其报告、决定放行/重跑 |
| 2 | **后端/平台工程师 A** | 后端核心、API v1、认证、密钥、Linux 部署 | **P0/P1/P2**，后 P6 | 可部署后端 + OpenAPI 契约 + `api-inventory` | 把机械重构（裁剪、容器化）交给编码 Agent，自己审 diff；冻结契约 |
| 3 | **移动端工程师 B** | React Native App、SSE 流式、TTS 音频、iOS/Android | **P5**，配合 P2 契约 | RN App + 解耦的 API 客户端层 | 用 Agent 生成类型/契约测试；后期原生迁移由 B 主导 |
| 4 | **全栈/前端工程师 C** | Web/PWA、Electron 桌面双目标、旧 jQuery UI 维护 | **P3/P4** | 双目标打包、PWA、模块拆分 | 用 Agent 做巨型模块拆分与回归用例生成 |
| 5 | **测试/QA & 安全工程师 D** | 聊天核心兼容回归、迁移验证、安全审查、备份恢复 | **贯穿 P0–P5** | 回归套件、合成 fixture、安全报告 | 用 Agent fan-out 生成用例、跑依赖漏洞扫描；D 做人工终审 |

## 3. 人手更少时的“合并”方案

| 实际人手 | 合并方式 | 代价 |
|----------|----------|------|
| **4 人** | 把 C（前端/桌面）并入你或 B；或把 D（QA）并入你 | P3/P4 或测试覆盖会变慢 |
| **3 人** | 你 + A（后端/DevOps）+ B（移动端兼前端）；QA 由你 + Agent 承担 | 回归与安全审计质量下降，风险上升 |
| **2 人** | 你 + 一名全栈（后端为主、移动端外包/延后） | 只推进后端主线，移动端延后到 P2 之后 |

> 建议：**至少保 1 名专职后端 A + 1 名专职移动端 B**，其余可压缩。QA 前期可由“你 + Agent”顶，但 P2 前后建议补一个专职测试，因为那是功能还原与兼容性的最大风险期。

## 4. 阶段推进矩阵（谁为主、谁支持、Agent 并行什么）

| Phase | 主责 | 支持 | Agent 并行任务 |
|-------|------|------|----------------|
| P0 裁剪/基线 | A | D（回归守门）、你（验收） | 编码 Agent 执行裁剪；审查 Agent 逐 commit 查“聊天核心是否被改” |
| P1 公网部署 | A | 你（安全边界） | 容器/Dockerfile 生成；配置环境变量清单生成 |
| P2 API v1 + 认证 | A（主）+ B（契约共定） | D（认证/归属测试）、C | OpenAPI 生成；测试 Agent 生成认证/越权/限流用例；契约文档 Agent |
| P3 桌面双目标 | C | A（平台接口） | 打包脚本生成；静态资源一致性回归用例 |
| P4 Web 解耦 | C | D | 巨型模块拆分（workflow fan-out）；CSP/CORS 配置生成 |
| P5 RN App | B | A（接口）、D（真机/模拟器测试） | 类型生成、端到端用例、iOS/Android 兼容测试清单 |
| P6（暂缓） | A | 你 | 暂不启动，人工明确后再排 |

## 5. Agent 分工（把重复劳动外包给 AI）

> 两种 Agent 都可用：① 外部编码 Agent（如 DeepSeek-Flash，按 `refactor-execution-checklist.md` 执行）；② 本工作区 Agent（Lead + 可长期存在的 teammate，共享同一文件系统，适合并行审查/生成）。

| Agent 角色 | 负责的活 | 触发方式 | 谁审结果 |
|-----------|----------|----------|----------|
| **编码执行 Agent** | 按执行清单跑 P0/P1 机械重构、容器化、脚本生成 | 你把清单文件地址丢给它 | A 审 diff + 你验收 |
| **代码审查 Agent** | 对每个 commit/PR 做 diff 审查，重点：聊天核心是否被改、是否泄露数据、验证是否真跑 | 每个 PR 自动触发 | A/C/B 人工终审 |
| **测试生成 Agent** | 为 API v1 生成认证/越权/限流用例；为 RN 生成端到端用例；为迁移生成合成 fixture | 每个 Phase 收尾 | D 审并补人工用例 |
| **安全审计 Agent** | 认证/密钥/限流/依赖漏洞扫描、隐私检查 | P2、P4 后各一次 | D + 你 |
| **契约/文档 Agent** | 维护 OpenAPI、`api-inventory`、roadmap/CHANGELOG | 每 Phase 收尾 | A 审 |
| **fan-out 并行 Agent（workflow）** | 大规模机械活：全库 grep 清理、`public/scripts` 模块拆分、多文件测试 | 需要并行时 | 你编排、各工程师审对应域 |

**Agent 使用纪律（关键）：**
1. 只让 Agent 做**可验证（有测试/命令）、可回退（git）、机械**的活；**架构决策、产品方向、安全红线、验收放行必须是人**。
2. 每个 Agent 任务必须有**明确的验收标准**（沿用执行清单里的“完成标准”与“报告格式”）。
3. Agent 产出一律进 PR，**人工审过才合入**；禁止 Agent 直接 push 主线。
4. 数据红线对 Agent 同样生效：不提交/不打印 `data/`、密钥、聊天内容。

---

## 6. 协作规则（把 5 人 + Agent 拧成一股绳）

1. **分支策略**：`main` 只收审查过的 PR；每 Phase 一个长分支（`phase/p0` …），Phase 内每 task 一个提交。
2. **PR 双重审查**：Agent 初审（红线检查）→ 对应领域工程师终审 → 你放行。
3. **统一验收门槛**（每个 Phase/PR 都要过）：
   - `npm run validate` 通过；
   - 聊天核心（`src/endpoints/chats.js`、`characters.js`、`prompt-converters.js`、JSONL 格式）**零改动**；
   - 遗留引用检测（执行清单 §附 B）**0 命中**。
4. **契约先行**：P2 的 OpenAPI 契约冻结前，B（移动端）与 C（前端）只做桩/骨架，不做深度开发，避免返工。
5. **每日同步点**：只问三件事——“今天有没有碰聊天核心？”“验证跑过没有？”“有没有数据/密钥进仓库？”。
6. **数据红线**：`data/`、`Config/`、密钥、聊天记录不进 Git、不进 Agent 输出、不进日志。

---

## 7. 上线前收尾清单（测试期结束时的“放行”标准）

- [ ] P0–P5 全部 Phase 完成标准达标（见执行清单）。
- [ ] 聊天核心兼容回归：普通聊天（所有 Leslie 模块关闭）全绿；角色卡/JSONL/Swipe/WorldInfo/群聊可用。
- [ ] `/api/v1` 全链路（注册→登录→聊天→SSE→TTS）在 Linux 服务器 + iOS + Android 三端各跑通一次。
- [ ] 安全：密钥明文不下发、越权测试通过、限流生效、依赖漏洞扫描无高危。
- [ ] 部署：容器 + TLS + 备份恢复演练通过。
- [ ] 数据迁移：桌面版老数据 → 服务器版路径有验证记录（含回滚）。
- [ ] 合规（商用前再补）：AGPL 源码提供、内容分级/年龄门控、数据删除/导出。
